# 高信息密度学术答辩PPT

默认采用有组织的高信息密度。让方法图、公式、局部放大、实验对照及短评共同解释一个研究问题；保留足够细节供评委判断研究工作。密度通过有用的信息和明确的关联建立。

## 使用入口

- 首次处理本课题，阅读 [1110版研究边界](references/proposal-1110-brief.md)，再核对用户当前提供的最新报告；旧简报不能覆盖新材料。
- 沿用胡、李模板时，阅读 [校内模板规范](references/neu-template.md)。请使用用户提供的校内模板文件。
- 组织方法、研究现状和实验页时，阅读 [高密度页面模式](references/dense-slide-patterns.md)。
- 了解规范依据与适用限制，阅读 [研究记录索引](references/research-sources.md)。
- 实际创建或编辑PPTX时，同时使用当前环境的 `pptx` 与 Presentations 技能；先加载该环境提供的演示文稿依赖。这里规定学术内容与视觉取舍，不绑定某一种生成库。

## 1. 读取材料，确定版本

先读报告中的研究目的、研究内容、技术路线、前期工作、评价方案和进度，再读模板与批注。记录输入路径、版本、哈希。保留原件，输出新文件。

提取四类信息：研究对象及场景；关键问题和对应方法；已有代码/图像/实验及其证据；尚待开展的工作。说明仿真、数据回放与实物验证的区别。报告未提供的参数、公式、结果不能自行补成事实。

明确汇报类型。开题主要论证问题有意义、方案具体、工作可实施、验证能回答问题；不得套用已完成论文的结果叙事。时长未给时先做可调整的页级方案，标明假设，继续不依赖时长的材料整理。

## 2. 建立论证链和逐页清单

按“应用需求→现有方法与剩余问题→研究目标→总体方案→关键方法→验证设计→已有基础与计划”组织。沿用学校或导师要求的章节名；章内标题写出具体对象、机制或待验证关系。

研究现状按问题或技术脉络比较：代表方法解决了什么，在何种条件下验证，与本课题还差什么，因而采用什么研究思路。引用必须支撑该项判断，不把尚未检索到的方案写成研究空白。

为每页建立记录，至少包括：

```text
页码 / 章节 / 标题
本页回答的问题与听众应带走的信息
研究状态：文献结论 / 本人已有基础 / 拟研究方法 / 拟验证
主图及子图关系 / 关键公式或约束 / 必要说明
输入→处理→输出 / 本人拟改进部分 / 验证方式
材料来源（原报告段落或图号、论文页码、数据或代码路径）
讲述顺序与估计时长 / 可能追问与备份页
```

先检查标题串联的逻辑，再检查每页的技术细节能否支持它。用户已授权制作时，不人为增加逐阶段审批。

## 3. 组织高密度内容

技术页通常设置3—5个有明确关系的内容区域，例如“主流程＋几何示意＋公式说明＋验证小表”。允许2—4个相关子图，并用(a)(b)(c)、箭头、共享颜色或同一坐标系关联。不是所有页都需要所有元素。

主流程图给全局关系；局部放大解释当前模块；公式解释计算或约束；短评解释选择理由；实验设计说明如何判断有效。每个元素必须服务本页问题，避免重复正文、无关图片、算法名称和品牌Logo堆积。

方法页至少说明：输入输出、主要步骤、关键假设或约束、相对基线的改动、验证方式。已有成熟模块可压缩，但本人拟研究部分应展开到机制和实施路径。

公式仅在帮助理解时使用：定义符号和单位，指出优化变量与约束意义，关联到图中对象。借用、推导和拟设计的公式要区分；不能为了显得专业而增加没有实现或来源的目标函数。

字数和元素数量不设通用硬上限。字体与密度以模板尺寸、投影可读性和试讲为准。出现过小标签时，优先裁剪无关背景、重绘图、缩短重复说明、调整区域比例；仍无法读清才拆页或移入备份。

## 4. 沿用模板并提升表现

保留指定模板的学校标识、尺寸、母版节奏、页眉页脚、主色和字体关系。从胡、李选择一个基础文件，另一份用于参考同一模板家族内的布局；不要将多个外校模板拼接。

胡、李为4:3，默认保留。迁移16:9必须有用户要求或明确场地条件。截图中的外校校徽、基金机构Logo、示例姓名及成果不能迁入本人答辩。

采用白底、深蓝标题、深色正文，图中增加少量有固定含义的颜色。方法图、表格、公式和关键标注尽量保持可编辑。文献原图可作为栅格图使用，注明来源并重设可读标注；不以整页截图代替最终可编辑PPT。

## 5. 维护学术证据与研究状态

- 引用就近标注作者、年份及短题名/来源，末尾附完整条目；编号与报告核对，改编图标明“据……改绘”。
- 数值、坐标轴、单位、样本量、基线设置和实验条件须可追溯。跨论文的数值不能当作同条件排名。
- “拟提高”“拟验证”不能写成“显著提高”“已解决”。已有截图只能证明其展示的现象，不能自动证明精度、实时性或实物安全性。
- 轨迹真值不足时，不用地图看起来整齐来替代ATE/RPE；有运行界面也不能据此声称整机完成。
- 明确已有算法、课题组基础、本人已实现内容与拟开展改进。不把系统集成直接包装成新算法。
- 大模型依据工具结果组织反馈；空间位置、碰撞与通行判断归地图和规划模块。未经确认，不把LLM生成内容当传感测量。

## 6. 讲述与备份

讲稿按“先看哪里→图中发生什么→为何这样做→怎么验证”组织，不逐字读页面。高密度页通过指示顺序和局部强调降低理解负担；导出的静态PDF也应保留完整逻辑，不能依赖动画才看懂。

按需要准备数据与标定、算法公式、基线与消融、失败案例、硬件部署、预算或进度的备份页。开题中的主要方法与验证逻辑不能全部藏到备份。时长不足时先删重复背景和装饰性过渡，再压缩技术细节。

## 7. 交付前检查

实际产出PPT后必须渲染全部页面，逐页查看，修改问题页后重新渲染相应页面，并检查总览一致性。

检查：母版和比例是否一致；字体是否替换；公式、图注与表格是否读清；箭头端点是否准确；是否溢出、遮挡、裁断或跨页格式漂移；图表是否真实；引用是否对应；已有与拟研究是否清楚；讲稿与页内容是否相符。

执行三项内容审查：

1. **需求对应**：每项研究内容对应明确任务，主要技术没有被场景故事挤掉。
2. **方法深度**：每项关键方法都能回答“具体怎样做、改哪里、受什么约束、如何验证”。
3. **证据边界**：每个结果和能力断言都有匹配层级的证据，未完成的工作保持计划语气。

交付可编辑PPTX、静态PDF、总览预览及适用的讲稿/引用清单，说明尚未核验的字体、动画、播放环境等实际限制。仅写规范或页面方案时，不声称最终PPT已经完成。
