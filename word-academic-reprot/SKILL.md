# word-academic-reprot

把研究材料写成证据可靠、逻辑连贯、图文一致、可编辑和可审阅的学术 Word 报告。不要依赖先前聊天、语音纠正或特定课题背景；从当前请求与材料建立完整上下文，在第一次交付前自行检查并修复明显问题。

## 先确定当前任务

- **从零新建或资料尚未成稿**：先读 [首次从资料到成稿](references/first_pass_workflow.md)，执行任务契约、证据整理、结构设计、完整写作和八项质量门槛；没有旧稿不是阻碍。
- **修改现稿**：先找到基准版本，确定允许改动范围，再执行下述局部修订流程。
- **模板迁移**：先确定内容基准与目标模板，读取 [Word 与图示](references/word_and_figures.md) 的迁移映射；不要把迁移当作重新写作。
- **只审查或答疑**：核实并报告，不自动改文件。
- 检查当前环境的资料读取、DOCX 制作和渲染能力。其他文档技能可增强执行，但不是本技能隐含前提；缺失时按首次流程末节的能力降级规则处理，不假称完成未执行的检查。

1. 修改现稿时，找到当前基准文件和用户已认可版本。区分用户原话、助手解释或计划、实际文件结果；不要将助手声称完成、历史检查标签或用户探索性技术猜测直接当事实或授权。分别记录“正在编辑”“供参考”“已撤回/被替代”的版本；不要仅凭文件名含“最终”或修改时间最新认定基准。
2. 从最新要求、模板、现稿和相关历史中提取当前约束：修改范围、输出形式、章节结构、字数、字体字号、行距、引文规则、图表样式、是否先给预览。旧反馈用于补全，不覆盖后续更正。
3. 区分三类内容：
   - **可复用原则**：先理解再写、按证据论证、保护已认可内容、检验图文与全文一致性。
   - **本次约束**：几段、几图、只改某节、某处不标引文、先给候选。仅适用于当前任务，后续变更及时替换。
   - **项目事实**：研究对象、模块数量、算法、设备、接口、参数和预算。每次以当前材料核实，不能当所有论文的默认方案。
4. 新建时记录任务范围、资料、输出结构与本轮交付粒度；修改时另建简短改动清单，包含“主稿路径与版本、仅供参考材料、位置、原问题、期望改法、证据、需保持不变的区域、本轮交付粒度”。用户上传片段作参考时，应修改其指定完整主稿，而不是误把片段当交付对象。语音中的口误和重复用相邻上下文、实际标题和后续确认消歧，不能把助手复述当用户的新要求。
5. 信息足够就执行。修改任务缺基准文件、影响论证的关键事实，或模板与最新要求的冲突无法判断时，只问最小必要问题；继续不受影响的部分。用户仅询问现稿内容时，先核实回答，不擅自改稿。技术答疑、临时构想、部署或微调设想保留讨论阶段属性，只有明确纳入当前研究方案后才成为改稿依据。

## 按顺序完成工作

### 1. 通读材料并形成内容地图

- 阅读完整相关章节、引用论文和图注，不靠摘要、检索片段或标题拼出综述。确实只获得摘要时标明证据范围，不声称已读全文。
- 概括整篇的研究问题、章节职责、核心方案、验证方法及章节之间的承接。修改小结前先了解本节整体发展脉络；改局部前读必要上下文，但只编辑授权范围。
- 为实质论断建立“论断—原文位置—来源—证据强度—适用范围”记录。把已完成、拟研究、他人结果、作者推断分开。
- 对技术流程结合论文、源代码、接口定义、实验材料与用户说明核对；材料冲突时指出差异并核实，不能拿通用流程替代实际实现。选方法先看场景、需求及功能匹配，再评估算力、实验成本和接入工作。读取 [技术方法与图义核验](references/method_and_figure_audit.md) 做方法选择、技术层次辨析和每条箭头的核对。

### 2. 写清研究主线

- 优先按**场景 → 需求 → 功能 → 既有方案及场景缺口 → 本课题方案 → 创新 → 研究与验证路线**组织相关章节。按学校模板安排这些要素，不强迫每段机械重复完整链条。理论或非系统型研究应改用研究问题、假设、变量、机制与实验等相应关系，不强行包装为产品系统。
- 从真实场景和证据自然引出需求。没有用户研究或来源时，将便携性、易操作性等写成设计考虑，不能仅换成“用户倾向于”就冒充已验证偏好。
- 先说明前人解决了什么，再指出与当前场景直接相关的缺口。只对有证据的能力或限制作结论；没有找到某能力的证据，不等于证明该能力不存在。
- 综述按研究脉络综合，不逐篇堆作者与结果。小结概括发展、现状和方向，不能只呼应开头或重复研究背景。
- 区分功能、研究内容、技术方法和创新贡献。模块之间有机协同形成系统集成创新时，写清整体价值；不能把几项功能机械改名为几个独立创新点。
- 保留自然、简洁的学术段落。把修改要求落实为正文，不在正文复述指令，例如不要写“而不将各模块视为独立创新点”。删除空泛过渡、重复解释和“为后文提供依据”等作者写作意图。保留必要的客观限制，不把减少无依据否定误解为禁止批判分析。
- 证据不足时不写过强结论；把资料取得范围、尚缺来源和本轮核验情况放简短交付说明，不能在每段末尾补“仅有摘要，不能据此……”等防御句。研究计划用“拟、将、计划”准确表示状态，必要的实验边界留在恰当章节，不将尚未完成研究反复写成免责尾句。
- 将技术层次辨析先用于工作核对，不把核对表逐条翻译为正文中的“不等于、不能据此、尚不足以”。逐段检查尾句：没有新增相关事实、只否定读者并未提出的假想能力、或复述编辑要求的，删除；保留直接影响比较结论的实验条件和真实限制。不要用禁词表机械删除一切否定表达。
- 需要具体写法和文献核验时，读取 [论证与证据](references/narrative_and_evidence.md)。

### 3. 设计图文与 Word

- 若当前环境提供 `documents` 或等效文档技能，读取并遵守其工具、模板、渲染与交付要求；若没有，按 [首次流程](references/first_pass_workflow.md) 的能力探测与可移植降级执行。本技能提供写作与验收规则，不假定固定工具名或软件已安装。
- 从当前模板与认可版本提取格式，不自定一套所谓通用学校标准。正文、中文标点、英文数字、引文上标、图注分别检查。
- 每幅图只承担明确的阅读任务：场景、需求对应、系统架构、流程、实验结果或产品使用方式。沿用认可样式，标签短而准，放在首次相关叙述附近。
- 图中显示关系，正文解释原因、证据与方法；不在图内、图下和正文三处重复同段说明。功能标签优先用平行动宾表达。
- 产品示例优先选能看清使用方式的真实场景图，核实产品身份、来源和成熟阶段。用户要求先挑选时，给带编号、简短说明与来源的图片候选，选定后才替换，不能仅丢链接代替图片。
- 修改图后联查图号、文内引用、图注、来源、后续编号和版面；不因加图重写已认可正文。
- 读取 [Word 与图示](references/word_and_figures.md) 完成具体制作和排版检查。

### 4. 做局部修改与回归检查

- 在基准副本上按改动清单作最小修改。用户逐段审阅或要求先记录时，先听完、收齐意见，不打断、不抢着解释；不要每听一条就擅自开始另一轮。禁止为局部修改从纯文本重建整份 Word 或全局重套样式；保留用户用 WPS/Word 调整的样式、段落、字段、媒体与修订结构。编辑前检查 run、域与书签，避免整段赋值抹掉上标、引文和其他行内格式。
- 保留已认可结构、语气和事实。只改图、删两句、调整分页，不等于获准全面润色；发现范围外问题先列出，不能顺手扩改。
- 每项纠正都搜索正文、图示、图注、表格、摘要、实验条件和预算，查同类残留；范围外的连带修改若未获授权，提示需要同步，不隐瞒矛盾。
- 对比前后文本及相关 OOXML/图片，确认未授权区域未变。仅文本相同不足以证明图片、样式和分页未变。核对非目标媒体、样式、编号、页眉页脚、批注和分节；允许自动变动的时间戳等元数据与内容变动分开判断。
- 读取 [迭代案例与验收](references/revision_patterns.md)，防止撤回稿回流、旧算法残留和已解决问题复发。

### 5. 验证再交付

- 做三轮检查：**内容/论证 → 引用/图文/全文一致性 → 渲染版式**。最终文稿不得夹带工具引用标记、未核实断言、写作过程说明或占位词。
- 用 `scripts/audit_docx.py` 辅助检查；它只读文件，不改正文，不替代学术和视觉审阅。将 `SKILL_DIR` 设为当前实际技能目录；输入和报告使用工作目录中的绝对路径，不在技能目录写任务产物：

```bash
python3 "$SKILL_DIR/scripts/audit_docx.py" /path/to/final.docx --numeric-citations --compare /path/to/baseline.docx --out /path/to/audit.json
```

- 新建稿没有比较基准时省略 `--compare`；不要为了运行示例索要不存在的旧稿。非数字制引用时省略 `--numeric-citations`。脚本输出启发式提示，须逐项人工判断；图片文字、域代码、脚注等需另查。`--compare` 同时列出 Word包内新增、删除、变动和未变的部件；字节不同须审阅，字节相同也不能替代正文语义与视觉检查。Word 自动参考文献编号只提示未解析，不自动作缺项结论。脚本退出成功只代表检查运行成功，不代表文稿合格。
- 使用当前可用的文档渲染流程渲染最终 DOCX，逐页查看图像；有 `documents` 技能时遵守其流程。检查页数、断页、留白、标题孤立、图注分离、裁切、中文标点字体、上下标和表格。每次再改都重新渲染受影响文件并复查。不能渲染时明确版式未验证，不将文本或包结构检查当视觉验收。
- 交付最新核验的用户所需文件。局部修改优先按本轮粒度给相关文字或真实截图，减少要求用户重读全篇；本轮明确要完整 Word 时交完整 Word，不以预览代替。提供指定章节截图时清楚标注对应位置。预览截图必须来自当前输出，而非旧稿或另排的样张。
- 用几句话说明修改了哪里、是否有仍待确认之处。只在实测后声称“检查完成”。分别记录本地保存、上传成功、发送已接受与实际送达，不把其中一个状态当成另一个；用户已收到或已确认的版本不要再次当待交付询问。遵守当前渠道的附件和权限规则。
