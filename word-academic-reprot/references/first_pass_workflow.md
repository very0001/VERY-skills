# 首次从资料到成稿

本流程用于没有历史对话、没有现稿或已有材料尚未成文的任务。以一次交付可审阅稿为目标，在交付前自行完成取证、结构推敲和修订；不要把发现明显问题的工作留给用户逐句纠正。质量检查降低遗漏风险，不保证任何课题均一次通过评审。

## 目录

- 最小任务契约与缺失信息
- 工作顺序：材料、结构、正文、图文与质量门槛
- 能力探测与可移植降级

## 最小任务契约

先从当前请求和附件提取以下内容，形成简短工作记录，不向用户逐项发问：

- 对象与问题：研究什么、在什么场景、解决谁的什么问题；哪些内容明确不在范围内。
- 报告用途与读者：开题、综述、阶段报告或其他类型；专业程度、截止时间。
- 交付物：正文片段、完整 DOCX、PDF、图源或预览；语言与篇幅。
- 证据：用户材料、论文全文、数据、代码、访谈或调研、可检索公开来源；各自已完成与计划状态。
- 结构与格式：用户指定模板、章节、引文制度、字体和图示要求；没有要求的项目不要伪装成学校规范。
- 本轮权限：新建还是修改，是否允许补充检索，哪些事实和方案已经确定，哪些仍待选择。

已有明确答案就直接采用。陌生课题不要求用户补充过去的聊天或语音；从本轮材料建立上下文。用户只提供主题时，可先提出合理的研究范围并标为建议，不能编造其学校、导师、已有设备、实验成果或调研结论。

### 缺失信息的处理

- **会改变核心选题或正式交付要求**：研究对象不明、互斥目标未决、要求严格套用但未提供的指定模板等，问最小必要问题，同时推进文献检索或材料梳理。不能自行替用户作出重大研究方向决定。
- **可安全暂定**：非强制封面信息、省略尚未要求的预算、无模板时的普通学术排版，采用可解释的暂定方案，在交付说明中点明。不要为一个未给出的姓名在正文塞占位符。
- **证据缺失**：先尝试授权范围内获取原文。只能得到摘要时，论述限于其明确记载；不能据此补实验机制或结论。删除不必要的无来源断言；关键事实无法核实则减弱为研究问题或设计假设，并保留其真实性质。
- **数据或实验尚未开展**：可以完成研究方案，写清拟获取的数据、验证设计和判断标准；不填造样本量、显著性、模型成绩和完成进度。为实验设计提出的样本或参数须明确是拟议选择，并解释依据及调整条件。
- **材料不足以写成合格最终稿**：交付有据的部分或清楚标注的草稿，列具体缺口及其影响，不用虚构参考文献或“待补”占满正式正文，也不把未完成包装为成稿。

区分取证不足与研究本身的不足。交付说明承载访问限制和待核验事项；正文承载有证据的学术问题、适用条件和研究计划。

## 工作顺序与中间产物

### A. 整理材料，而不是先堆正文

建立两个轻量工作表，留在工作记录中，不自动附入正式稿：

1. **来源表**：稳定来源 ID｜准确身份与版本｜原文位置｜实际阅读范围｜关键证据及限制｜拟支撑章节。
2. **论证表**：当前研究问题｜相关场景证据｜已有方法及适用边界｜拟开展工作｜比较对象｜评价方式。

以问题决定检索和材料缺口。优先读原始研究与可靠原始统计；综述用于定位和综合，不冒充对其全部引文的独立阅读。题目中的关键词相关不代表实验对象、任务或结论可以移植。每个核心比较结论都应能回到明确来源，不能仅给文末书目。

### B. 先搭能解释的结构

按当前模板给每节写一句“本节回答什么、怎样推进全文”，再为段落分配作用。没有模板时，可用问题背景、相关研究、研究目标与内容、实施与验证、计划与条件等职责组合；不是每类报告都必须用同一套标题。

检查三条链：

- **论证链**：场景事实或合理研究问题 → 需求或目标 → 现有方案及相关缺口 → 拟解决的问题。
- **工作链**：研究问题 → 方法与输入输出 → 数据/实验 → 比较与指标 → 可判断的结论。
- **阅读链**：开头提出主线 → 中间比较和推进 → 结尾综合回答，不忽然引入未经铺垫的新模块。

纯理论、实验科学或非系统课题可将“功能/模块”替换成假设、变量、机制和实验，不强行写成产品系统集成创新。创新未证实时写拟探索的贡献和验证方法；选用热门模型或拼接现有模块本身不是已成立的创新。

### C. 写出第一版完整正文

按结构连贯成文，段落通常包含必要论点、证据及解释；这是推敲方法，不是每段固定三句的模板。

- 先给事实、方法实际作用和比较关系，再给有限结论。保留与当前问题有关的限制，删不提供信息的否定尾句。
- 按读者知识水平确定解释深度；新术语首次出现时解释其在本研究中的作用，避免通篇基础科普。
- 综述比较同一问题上的差异，正文区分前人成果、本次推断和拟开展工作。不能把未来实验写成既得成绩。
- 实施方案写到另一位研究者能理解“收集什么、怎样处理、如何比较、什么结果支持或反驳假设”。依据课题考虑数据划分、信息泄漏、混杂因素、重复试验、统计不确定性、失败条件或安全边界，不机械要求所有课题使用同一种实验。
- 比较设计与所问结论保持同一层级。要判断某项特征、模块或机制的增益，在相同基础方法、数据划分和评价条件下设置有/无该因素的对照，或给出适当的替代识别设计；若同时改变模型、数据和输入，只能支持整体方案比较，不能单独归因于其中一个变化。
- 计划与资源适合当前可用条件；缺少资源信息时说明依赖，不虚构购买预算或批准状态。涉及参与者、个人数据或高风险实际试验时，说明所需伦理、隐私和安全安排，不代替正式审批。
- 先让每节承担不同职责，再删除跨节同义重复。摘要或总结概括主要内容，不重新堆一遍模块清单。

### D. 制作实际可读的 Word 与图

先确定版面和字体再制作图，按图在最终页面上的尺寸设计。不要先做满屏可读的图，再缩到 Word 中任由文字不可辨。读取 `word_and_figures.md`，按图的阅读任务选择结构；无图也能说明问题时，不为装饰额外加图。

新建稿使用语义样式管理标题、正文、图注和书目。没有模板时可采用 A4、适度页边距、清楚的标题层级与统一段间距等常规版式，但把具体选择当本稿方案，不宣称为学校标准。依实际已安装字体制作；指定字体缺失时不能悄悄用别的字体并报告已满足。

保留可编辑 DOCX 和自绘图源。自绘结构图的内容来自当前方案，不冒充论文原图或实测结果；所引原图逐图保留来源和改编状态。图文名称、编号、箭头、条件和引用一致后再嵌入，嵌入后查看实际页面。

### E. 对首稿执行质量门槛

以下检查在发给用户前完成。检出问题先自行修复，再复核受影响内容；不要把“请用户再看看”当检查的替代。

1. **任务门槛**：交付类型、范围、语言、篇幅及指定章节逐项满足。未经授权的扩展已移出正文；未决核心选择已明确。
2. **证据门槛**：核心外部事实、数值、比较和归属均可追溯；无捏造来源、元数据和阅读经历；取得的摘要不支持正文未核实细节。研究计划没有被写成结果。
3. **叙事门槛**：仅看各节首尾也能复原研究主线；每段有明确职责；方法组之间的承接基于问题，不暗示虚构的技术继承；结尾没有空泛否定或编辑指令。
4. **可执行门槛**：每项主要研究内容都有输入、工作、产物和验证方法。目标、假设、方法、评价指标彼此匹配；结论涉及单个因素增益时有对应受控对照，而不只比较两个多处不同的方案；关键资源依赖和可行性限制可见。
5. **引用门槛**：显示编号与稳定来源身份一致；正文及图注引用均能找到条目；条目准确且被实际使用；正式出版与预印本身份不混。按要求检查顺序、样式和链接，脚本提示须人工判断。
6. **图文门槛**：每幅图有清楚用途和正文承接；实际技术关系正确，最终显示尺寸可读，无多余重复或密集跨线；示意与实验结果、原图与改绘图区分清楚。
7. **格式门槛**：打开并渲染最终文件，逐页检查标题、表格、图注、字体、标点、页码、断页和裁切；上标引文、图例与注释需按最终有效尺寸单独检查，不能以放大截图或源文件名义字号代替正常阅读尺度。封面、目录、交叉引用如存在则同步核对。自动文本检查不能代替逐页看图。
8. **交付门槛**：交付确为最新核验版本，源文件可打开；说明未通过、未执行或依赖用户补充的项目。只有全部适用门槛通过，才称对应范围已检查；“完整 DOCX 已保存”不意味着科学结论已证明或正式提交要求已满足。

每次交付保留一条简短验收记录：最终文件路径与版本、格式方案、渲染页数和已查看页数、文献/图源核验范围、问题修复结果、未解决或未执行项。记录供工作交接使用；用户说明只保留影响其使用的关键信息，不自动附上冗长核对表。

## 能力探测与可移植降级

调用前检查实际环境，而不是假定安装了特定技能或程序：

- **文件读写**：确认能读输入与写指定目录；缺权限不改用未授权路径。用户只要求本地保存时不上传或安装。
- **资料读取**：优先可用的 PDF、Word、网页读取能力；只有文本抽取时不能声称看过原图和版式。
- **DOCX 制作**：有 `documents` 或等效文档技能就读取并遵守；没有时，使用环境已有且适用的文档库、编辑器或 OOXML 工具。新建稿应使用结构化样式；局部修改必须保存既有结构。不能将改扩展名的纯文本冒充 DOCX。
- **渲染与视觉检查**：优先使用可用的 Word/LibreOffice、文档服务或等效渲染器生成预览，并实际查看每页。若无法渲染，仍可检查文本、OOXML 与引用，但明确“版式尚未验证”；不要把未验证稿说成已排版验收。
- **辅助脚本**：随技能提供的 `scripts/audit_docx.py` 仅需 Python 3 标准库。无 Python 时以解包 XML 或可用编辑器做相同范围检查，明确未运行脚本。它不是排版器，也不核验论文真实性。
- **缺少必要能力**：能完成哪些就完成哪些；不能生成所需文件时提供清楚标注的正文草稿或说明最小缺口，不能谎称创建、保存或发送成功。若用户明确要求最终格式合格，缺失能力是待解决项，不是自动降低其验收标准的许可。
