# 交付、README 与验收

## 工作空间根目录 README

提供项目目的、能力与范围、支持的平台与 ROS 版本、源码/包概览、系统依赖与 Python 依赖、模型/数据准备、从干净环境构建、启动命令、就绪标志和常见故障。给出一条清楚、直接的主启动方式及必要参数；如果外设或底盘配置在项目外，说明边界与前提。代码、日志和下载文件在哪里，由项目约定说明，不制造多余包装。

区分“目标机已具备兼容的 OS、ROS 2、colcon 和 rosdep”与“从空系统开始安装”：前者说明自检与前提；后者按目标发行版官方步骤说明 ROS、构建工具及 rosdep 首次初始化，架构或版本不兼容时明确阻塞。命令使用明确的工作空间位置，但不依赖作者的用户名。例如让读者先在其实际工作空间根目录打开终端：

```bash
# 首先 source 目标系统实际安装的 ROS 2 环境
rosdep install --from-paths src --ignore-src -y
python3 -m pip install -r requirements.txt  # 仅当清单适用当前解释器和环境时
colcon build
source install/setup.bash
```

这些是常见步骤而非免检通用安装脚本：先确认 rosdep 可用、安装权限、环境解释器、实际依赖和顺序；如需虚拟环境，先创建并解释 ROS 绑定如何可用。为新 shell 写明重新 source；没有 requirements 时不写无效命令。若原本已有受约束的环境入口，说明其作用及实际路径。构建从工作空间目录执行，或用 colcon 的 `--log-base` 将日志指定在工作空间，避免散落到其他目录。

## 每个功能包一份完整 README

保留一份 Markdown README，合并原有有价值的功能、用法和部署说明；不擅自删除需要的信息。至少覆盖：

1. 职责、输入输出、接口名称/类型及其语义、依赖及本包目录。
2. `src/` 节点和实现、`include/` 中每类头文件/共享实现/资源的实际作用；不存在的目录不编造。`config/`、`launch/`、接口文件等按实际介绍。
3. 编译与环境准备，复制后即可操作的独立运行示例、真实可用的示例输入或准备方法、预期输出和退出方式。命令必须从新 shell 按文档顺序实测；禁止假设读者已经 source 了工作空间或在正确目录。
4. 参数、默认值、配置与资源位置，如何切换或扩展配置/插件；如果存在提示词、Schema 或其他业务配置，说明修改位置、格式、安装方式、重编译/重启要求和影响。
5. 常见报错、解决办法和硬件/模型的前置条件。文档不要把过期路径或临时回放文件写成永久可用输入。

## 分层验证

- **包级**：构建与 `ros2 pkg` 发现；基础节点独立启动，典型及错误输入输出正确；安装后资源能读取；针对修改的逻辑执行必要测试。
- **接口和组合**：自定义接口能生成及导入，检查消息类型、QoS、参数传递、launch、各节点连接、就绪、退出与异常；如业务需要，检查取消和旧结果处理。
- **迁移和部署**：新 shell、不同工作目录、无源码路径依赖的安装结果；可能时使用目标架构上的干净环境照 README 重建。记录实际使用的 ROS/系统/Python/依赖/模型版本。不能只靠当前机器的预装环境证明换板可用。
- **端到端**：录音/rosbag 回放、仿真、实际设备逐项区分；有硬件动作时按当前授权和设备状态进行。没有验证的步骤明确标记未验证，不推导为实机通过。
- **性能（适用时）**：说明目标设备、模型版本、量化、线程、输入、预热状态、采样区间、重复次数以及统计口径；分项记录延迟、CPU（说明归一化方式）、内存（RSS/PSS/系统可用内存等）、必要的端到端耗时。相同任务和条件比较，缺记录写未记录，不用其他设备结果或猜测填空。

完成后简明交付：哪些包、命令和能力已验证，依赖/模型如何准备，哪些内容未验证，哪些风险需用户人工验收。发布、删除、部署和外部消息按用户具体授权执行；保留非本任务的修改和用户数据。
