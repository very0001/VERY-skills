# 工作空间与功能包

## 从一开始设计

在写节点之前，画出功能流和依赖方向：基础功能互相通过契约连接；组合包依赖基础包，基础包不反向依赖组合包。按变化原因、独立运行和复用需求划分功能，不按每个函数、每一种设备硬拆一包。功能包名称应符合所用 ROS 2 工具链的命名要求、体现职责。

下图是**示意**，不是要求每个包都创建全部目录：

```text
robot_ws/
├── src/
│   ├── input_module/            # 独立基础功能包
│   │   ├── src/                 # 节点入口及源码（按语言组织）
│   │   ├── include/             # 公共头文件、项目约定的共享实现或资源
│   │   ├── config/              # 参数、资源清单等（按需）
│   │   ├── launch/              # 此模块的独立启动（按需）
│   │   ├── test/                # 测试（按需）
│   │   ├── package.xml
│   │   └── README.md
│   ├── processing_module/       # 可独立使用的基础功能包
│   ├── robot_interfaces/        # 仅有必要时设立，msg/srv/action 按需
│   └── robot_bringup/           # 系统组合包：launch、配置和协调逻辑
├── build/                       # colcon 构建生成
├── install/                     # colcon 安装生成
├── log/                         # 构建和项目约定的运行日志
├── README.md
└── requirements.txt             # 存在 pip 依赖时
```

`package.xml` 是每个 ROS 包的清单，但其他构建文件视构建类型而定。`ament_cmake` 包一般有 `CMakeLists.txt`；`ament_python` 包使用 `setup.py` / `setup.cfg`、resource index 和 Python 模块等，不要求为了样式额外建立 CMakeLists。消息生成通常使用 `ament_cmake` 和 rosidl。用 `colcon list` 检查发现结果，避免嵌套包被漏发现、重名和依赖环。

## 基础功能包

- 每包说明输入输出、职责和不负责的内容；节点的参数、设备和资源位置可配置，不隐式依赖其他功能包的某个启动脚本。
- 新建项目按用户偏好把入口源码放包内 `src/`；已有项目保持既有布局，除非用户要求调整。Python 标准 ament_python 也可以使用包名目录；若采用 `src/` 布局，必须配置 setuptools 的包发现和映射。C++ 公共头文件遵循 `include/<package>/`；用户指定 `include/` 为共用实现或资源目录时，正确设置 Python 包映射、CMake 安装或数据文件规则，确保编译后的导入与路径有效。
- Python 需遵循解释器导入和 setuptools 包发现机制；`__init__.py` 是 Python 包的一部分，不能为了视觉目录整洁直接移动或删除。`__pycache__` 是运行缓存，不纳入源代码版本管理。检查 `setup.py` 的包发现/`package_dir`、`console_scripts`、resource marker 和 `package.xml` 安装，以及 `setup.cfg` 的执行入口位置；普通安装后在新 shell 验证 `ros2 run` 与模块导入。
- 提供适合的独立节点运行方式和可重复的单模块验证输入。例如传感器包可用录制数据，处理包可用话题注入，纯算法可脱离 ROS 做单元测试。与功能相关的依赖只声明给实际需要的包。
- 目录树只是设计意图；README 要以真实文件与真实命令为准。不要为满足模板复制空文件夹，不把第三方实现或多个版本任意散落在包根目录。

## 系统组合包

用有意义的包名，不固定叫 AGENT。提供一个或多个 `launch/`，选择已启用的基础节点并传入参数及资源配置；动态状态、超时、重试和业务流程由组合包中的协调节点负责，不把 launch 当作运行期状态机。组合层可有节点实现流程控制，但不得拷贝基础算法或依赖基础包的私有源码路径。

参数不同、提示词不同或工作模式不同的组合可用 launch 参数及配置选择；说明选择方式和默认值。确有新组合需求时优先扩展组合层；仅当基础能力本身不足时才修改或扩展基础包。

## 自定义消息与接口

优先选择语义、单位和时间约定合适的标准消息；确实有稳定的跨包契约无法表达时，在独立接口包中按需创建 `msg/`、`srv/`、`action/`，为字段、单位、坐标系、状态码、版本和兼容性写说明。相关 `package.xml`、`CMakeLists.txt`、rosidl 生成依赖必须齐全；生成之后在新 shell 验证能否发现、导入及跨包使用。

相关接口可集中到同一个接口包，但按项目规模和复用边界判断，不为了统一而引入不必要的全局耦合。接口包不依赖消费它的业务包；保留兼容性，已有类型更名或删除前确认影响。
