# 成对短事务（显式允许短暂阻断实体应用输入）

`semantic_cu.auxiliary_transaction.run_batch(actions, window, acknowledge_keyboard_interruption=True)`

调用端须已取得用户允许短暂等待的授权，且设置原实验开关 `SEMANTIC_CU_ENABLE_AUX=1`。具体授权由调用 Host 针对当前任务确认；这不是一般应用永远无干扰的保证。旧持久会话接口及其兼容拦截保持不变。新增MCP入口 `desktop_aux_batch`，要求host_approved、observation_id、acknowledge_keyboard_interruption、actions，可选max_seconds。新启动的网关会加载；现有服务需要重新加载才能获得新接口。

一次调用内先校验整个动作序列，创建一对设备，单个原生子进程/连接执行连续动作，finally清理设备后才返回。失败不重试，避免重复文字/点击。动作仅move/click/text/scroll；最多128步、ASCII文本总计4096字符，按5–120秒执行预算预校验，保留13ms/字符，不调整全局输入法或剪贴板。批次使用24×32原生青色箭头与深色边框，无标签、无叠层。显式位图避免主题ARGB光标无法重着色的问题；目标子窗口一并设置，只影响本批次辅助指针。光标资源持有到设备移除后再释放，不逐动作重建。

监督进程维持既有会话超时、显示锁和退出清理；原生worker有父进程死亡保护和指定预算调用超时，设备监督超时为本次预算。清理失败不能报成功，需要既有显式旧租约恢复。Xorg自身崩溃仍可能影响整个桌面，超时机制不能预防显示服务器崩溃。实体Chrome键盘在设备存在期间仍可能不可用；跨批次不保留按住键或焦点承诺。

MCP网关在受控线程执行批次，同连接可处理授权stop/pause并取消批次；取消关闭监督输入，监督器停止原生worker并在显示锁内移除设备。stop等待清理完成，不能仅因发出取消就声称已恢复。其他冲突操作在批次进行时拒绝。普通工作优先短批次，长输入只在用户允许短暂等待时使用。未修改打字速度，未声称原Xorg崩溃根因已修复。
